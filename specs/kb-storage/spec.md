# Spec: kb-storage

Status: draft, awaiting approval · Owner: Surya Prakash Giri · Ticket: none (personal repo; `tasks.md` is the task list)

## Problem
Ingestion, retrieval, both agents, leads and alerts all need somewhere to keep state: operational records in
MongoDB, vectors in Qdrant, hot conversation turns in Redis, and raw files encrypted on disk. Admin routes also
need authentication before any of them exist. The vault has to move between machines (macOS/podman →
Windows/docker) without losing data or leaking it in transit.

## Goals
1. **MongoDB via Beanie on the PyMongo Async API.** The client is created in the app lifespan. Indexes are
   declared on the document classes and created at startup. Versioned data migrations go in `migrations/`, each
   with an applied-marker document.
2. **Collections** (data model below): `api_keys`, `sources`, `documents`, `chunks`, `records`, `profile`,
   `leads`, `conversations`, `messages`, `security_events`, `audit_log`, `model_overrides`.
3. **Conversations, Redis cache-aside:**
   - `append_turn` writes the turn to Redis first (`conv:{id}`, capped list of the last N turns, TTL by channel:
     public 24 h, owner 14 d), then persists it to MongoDB in the background with retry. A persistence failure is
     logged and counted, never raised to the caller.
   - `history(conversation_id)` reads Redis and, on a miss, loads from MongoDB and repopulates the cache.
   - Public conversations and messages expire after 90 days (MongoDB TTL index on `expires_at`).
   - Visitors are identified only by a salted hash (`VISITOR_HASH_SALT`); raw IPs are never stored.
4. **Qdrant collections** are created idempotently at startup: `kb_public`, `kb_private`, `kb_confidential`. Each
   has a named dense vector (`dense`, size `EMBEDDING_DIM`, default 384, cosine) and a named sparse vector
   (`sparse`, IDF modifier), plus payload indexes on `tier`, `document_id`, `category`, `published`. The public
   deployment profile creates `kb_public` only.
5. **Encrypted blob store** for raw files, under `vault/blobs/`:
   - Fernet, with the key in `BLOB_ENCRYPTION_KEY` (generated by `setup`, never printed).
   - Content-addressed by SHA-256 of the plaintext, so the same file is stored once.
   - API: `put(bytes, content_type) -> BlobRef`, `get(ref) -> bytes`, `delete(ref)`.
6. **Admin auth:**
   - `X-API-Key` keys look like `atw_` + 32 random bytes (URL-safe). Only a SHA-256 hash is stored.
   - Scopes: `admin`, `public:read`, `leads:write`.
   - The `require_scopes(...)` dependency returns 401 `AUTH_REQUIRED` / `AUTH_INVALID` and 403 `FORBIDDEN`.
   - `last_used_at` is updated at most once a minute.
   - Admin routes are mounted only when `DEPLOYMENT_PROFILE=vault`.
   - Script `keys create|list|revoke`. `create` prints the plaintext once.
7. **Model overrides persisted:**
   - The `model_overrides` collection holds per-model `enabled` / `max_tier` and per-role chains.
   - Admin routes `GET /admin/v1/models/overrides` and `PUT /admin/v1/models/overrides/{model_id}` validate the
     shape with pydantic and record an audit-log entry.
   - Wiring the store into the orchestrator is a one-task follow-up once llm-orchestrator and kb-storage are
     both merged; it is the first task of ingestion.
8. **Vault export/import:**
   - `export` writes one archive under `vault/exports/`, encrypted with a passphrase-derived key (scrypt +
     Fernet). The passphrase comes from a prompt, or from `EXPORT_PASSPHRASE` for automation, and is never
     stored.
   - Contents: `mongodump --archive` run inside the mongo container, a Qdrant snapshot per collection taken
     through the API, the blob store, and `manifest.json` with SHA-256 per part, the source machine's runtime,
     and versions.
   - `import` verifies every checksum before touching anything. It is a dry run by default; `--apply` restores
     into the running stack (`mongorestore --drop`, snapshot upload/recover, blobs) and re-creates indexes.
   - Works with docker or podman, through the existing compose helpers.
9. `/readyz` keeps its three checks. Startup fails fast with a clear log line if MongoDB auth fails.

## Non-goals
Ingestion pipelines, embeddings and chunking (ingestion); retrieval; agent checkpointer wiring (owner-agent);
cloud deployment and publish sync (deploy-public); the semantic cache.

## Data model (MongoDB)

| Collection | Key fields | Indexes |
|---|---|---|
| `api_keys` | `name`, `key_hash`, `scopes[]`, `created_at`, `revoked_at?`, `last_used_at?` | unique `key_hash` |
| `sources` | `kind` (text/file/url/github/linkedin_export), `uri?`, `filename?`, `checksum`, `blob?`, `status`, `created_at` | unique `checksum`+`kind` |
| `documents` | `source_id`, `title`, `category`, `tags[]`, `domain`="career", `tier`, `label{tier, reason, by, confidence}`, `review_status`, `published`, `published_at?`, `occurred_at?`, `deleted_at?` | `review_status`, `tier`, `published`, text index on `title` |
| `chunks` | `document_id`, `ordinal`, `text` (redacted), `tier`, `qdrant_point_id`, `canary`, `published` | `document_id`+`ordinal` unique |
| `records` | `kind` (application/interview), `company`, `role`, `stage`, `date`, `notes?` | `kind`+`date` |
| `profile` | singleton: `availability`, `notice_period?`, `preferred_roles[]`, `locations[]`, `resume_blob?`, `updated_at` | — |
| `leads` | `name`, `email`, `company?`, `role?`, `message`, `summary?`, `triage?`, `conversation_id?`, `emailed_at?`, `created_at` | `created_at` |
| `conversations` | `channel`, `visitor_hash?`, `created_at`, `updated_at`, `message_count`, `expires_at?` | TTL `expires_at`, `channel`+`updated_at` |
| `messages` | `conversation_id`, `seq`, `role`, `content`, `intent?`, `guards{}`, `max_tier?`, `model?`, `trace_id?`, `tokens?`, `latency_ms?`, `created_at`, `expires_at?` | unique `conversation_id`+`seq`, TTL `expires_at` |
| `security_events` | `kind`, `severity`, `details{}`, `visitor_hash?`, `created_at`, `alerted_at?` | `kind`+`created_at` |
| `audit_log` | `actor`, `action`, `target`, `details{}`, `at` | `at` |
| `model_overrides` | `_id`=model id or `role:<role>`, `enabled?`, `max_tier?`, `chain[]?`, `updated_at` | — |

## API

| Method | Path | Scope | Purpose |
|---|---|---|---|
| GET | `/admin/v1/models/overrides` | admin | list stored overrides |
| PUT | `/admin/v1/models/overrides/{model_id}` | admin | upsert one override (audited) |
| GET | `/admin/v1/whoami` | any valid key | key name and scopes (auth smoke test) |

## Configuration
New settings: `BLOB_DIR` (default `vault/blobs`), `BLOB_ENCRYPTION_KEY`, `VISITOR_HASH_SALT`, `EMBEDDING_DIM`,
`QDRANT_API_KEY`, `CONVERSATION_CACHE_TURNS` (default 20), `PUBLIC_CONVERSATION_RETENTION_DAYS` (90).
`setup` generates the secrets on a fresh `.env` and appends any new keys to an existing `.env` without touching
existing values.

## Acceptance criteria
1. Startup creates every MongoDB index and Qdrant collection idempotently; a second start changes nothing.
2. The `public` profile creates only `kb_public` and mounts no admin routes.
3. `append_turn` returns after the Redis write. A failing MongoDB write is retried, logged and does not raise.
   `history` after a Redis flush returns the same turns from MongoDB.
4. Public conversation documents carry `expires_at` ≈ now + 90 days. Owner ones have none.
5. A stored blob is unreadable without the key. Re-putting the same content returns the same ref.
6. Missing key → 401 `AUTH_REQUIRED`; unknown or revoked → 401 `AUTH_INVALID`; wrong scope → 403 `FORBIDDEN`.
   The plaintext key is never stored or logged.
7. Override PUT validates `max_tier` in `public|private|confidential` and writes an audit entry.
8. `export` → `cleanup --apply` → `setup` → `import --apply` restores identical document counts, Qdrant point
   counts and blob checksums. A tampered archive is refused before any restore.
9. `make check` passes. Unit tests use fakes; MongoDB/Redis/Qdrant round-trips are `integration` tests run
   against the compose stack.
